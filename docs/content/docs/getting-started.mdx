## Prerequisites

Before you begin, make sure you have the following installed:

- **Docker** and **Docker Compose** (for PostgreSQL, ClickHouse, Redis, NATS)
- **Go 1.26+** (for the API server and gateway)
- **Node.js 20+** and **npm** (for the dashboard)
- **Python 3.9+** (for the Python SDK)
- **Git**

## Clone and Setup

Clone the repository and start the infrastructure services:

```bash
git clone https://github.com/traceform/traceform.git
cd traceform
```

Copy the environment file and configure it:

```bash
cp .env.example .env
```

Start the infrastructure services (PostgreSQL, ClickHouse, Redis, NATS):

```bash
docker compose up -d
```

Wait for all services to be healthy:

```bash
docker compose ps
```

You should see all four services running: `postgres` (port 5432), `clickhouse` (ports 9000/8123), `redis` (port 6379), and `nats` (port 4222).

## Run Database Migrations

Apply all database migrations:

```bash
make migrate
```

Seed the database with pre-built failure patterns, evaluators, guardrails, and model pricing:

```bash
make seed
```

## Start the Servers

Start the Go API server (port 8080):

```bash
make dev
```

In a separate terminal, start the Next.js dashboard. Port 3000 may be taken by other applications, so use port 3001:

```bash
cd web
npm install
PORT=3001 npm run dev
```

Verify the API server is running:

```bash
curl http://localhost:8080/health
```

Expected response:

```json
{
  "status": "healthy",
  "version": "0.1.0",
  "time": "2026-03-21T12:00:00Z"
}
```

You can also check the readiness endpoint, which verifies all dependencies:

```bash
curl http://localhost:8080/ready
```

```json
{
  "status": "ready",
  "checks": {
    "postgres": "healthy",
    "redis": "healthy",
    "nats": "healthy",
    "clickhouse": "healthy"
  }
}
```

## First Login (GitHub OAuth)

Open [http://localhost:3001](http://localhost:3001) in your browser. Click **Sign in with GitHub** to authenticate.

On first login, Traceform automatically creates:
- A personal **organization** for your account
- A **default API key** for SDK access (prefixed with `tf_sk_`)
- An **owner** role for your user (RBAC is enforced on all mutation routes)

If GitHub OAuth is not configured in your `.env`, you can set it up by creating a GitHub OAuth App and adding the credentials:

```bash
GITHUB_CLIENT_ID=your_client_id
GITHUB_CLIENT_SECRET=your_client_secret
```

## Create Your First API Key

Navigate to **Settings > API Keys** in the dashboard, or use the default key created during login.

API keys use the format `tf_sk_...` and are passed as Bearer tokens in the `Authorization` header.

You can also manage API keys via the dashboard API:

```bash
# List API keys (requires JWT from dashboard login)
curl -H "Authorization: Bearer <jwt_token>" http://localhost:8080/api/api-keys
```

API keys support rotation with a 24-hour grace period via `POST /api/api-keys/{id}/rotate`.

```bash
pip install traceform[openai]      # OpenAI auto-instrumentation

```

## Send Your First Session Trace

Create a file called `quickstart.py`:

```python
import traceform

# Initialize the SDK with your API key
traceform.init(
    api_key="tf_sk_your_key_here",
    endpoint="http://localhost:8080",
)

# Create a tracing session
with traceform.session(agent_name="my-first-agent") as session:
    # Create a span for an LLM call
    with session.span("generate-greeting", span_type="llm_call") as span:
        span.set_input({"prompt": "Say hello"})
        span.set_model("gpt-4o", provider="openai")

        # Simulate an LLM response
        result = "Hello! How can I help you today?"

        span.set_output(result)
        span.set_tokens(input_tokens=12, output_tokens=9)
        span.set_cost(cost_cents=1)

    # Create a span for a tool call
    with session.span("search-docs", span_type="tool_call") as span:
        span.set_input({"query": "traceform setup"})
        span.set_output({"results": ["Getting Started guide"]})

print(f"Session ID: {session.id}")
print(f"Status: {session.status}")
print(f"Total tokens: {session.total_tokens}")
```

Run it:

```bash
python quickstart.py
```

## View Data in the Dashboard

Open [http://localhost:3001/dashboard/sessions](http://localhost:3001/dashboard/sessions) to see your session in the **split-pane session explorer**. The left pane shows the session list with infinite scroll; select a session to see its details in the right pane.

### Split-Pane Explorer

The sessions page uses a master-detail split view:
- **Left pane**: Session list with infinite scroll and server-side pagination, search, and filtering.
- **Right pane**: Session detail with the D3 Gantt chart timeline, span tree (virtual scrolling for large traces), and metadata.
- **Keyboard navigation**: Use arrow keys to move between sessions.

### Time Range Picker

A global time range picker appears on all data pages. Choose from preset ranges: **15m, 1h, 4h, 1d, 7d, 30d**.

### Auto-Refresh

The overview page at [http://localhost:3001/dashboard/overview](http://localhost:3001/dashboard/overview) supports auto-refresh with configurable intervals: **Off, 10s, 30s, 1m**.

Navigate to the overview page for aggregate metrics including session count, failure rate, total tokens, and cost.
