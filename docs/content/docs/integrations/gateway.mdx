# Gateway Integration (Zero Code)

The Traceform Gateway is an OpenAI-compatible proxy. Route your LLM calls through it to get automatic tracing, guardrails, caching, cost tracking, and failover — without changing any application code.

## How It Works

```
Your App / n8n / Flowise
        │
        │  1. Send request to Traceform Gateway
        │     (instead of directly to OpenAI)
        │
        ▼
Traceform Gateway (:8090)
        │
        │  2. Authenticates with your Traceform API key
        │  3. Applies guardrails (PII, injection, toxicity)
        │  4. Checks semantic cache
        │  5. Routes to the right provider
        │  6. Uses YOUR provider API key (stored encrypted in Traceform)
        │  7. Logs the request for tracing + cost tracking
        │
        ▼
OpenAI / Anthropic / Google / Local Model
```

**Key point:** Your LLM provider API keys (OpenAI, Anthropic, etc.) are stored securely in Traceform. You add them once in the dashboard, and the gateway uses them for every request.

## Setup (3 Steps)

### Step 1: Add Your LLM Provider in Traceform

Go to **Dashboard → Gateway → Providers** and add your LLM provider:

```bash
# Or via API:
curl -X POST http://localhost:8080/v1/gateway/providers \
  -H "Authorization: Bearer tf_sk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "openai",
    "display_name": "OpenAI",
    "api_key": "sk-your-openai-key-here",
    "base_url": "https://api.openai.com/v1",
    "is_enabled": true
  }'
```

Your OpenAI API key is encrypted (AES-256-GCM) before storage. It never appears in API responses.

### Step 2: Add a Routing Rule

Tell the gateway which models map to which provider:

```bash
curl -X POST http://localhost:8080/v1/gateway/routes \
  -H "Authorization: Bearer tf_sk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "OpenAI GPT-4",
    "model_pattern": "gpt-*",
    "provider_id": "PROVIDER_ID_FROM_STEP_1",
    "target_model": "gpt-4o",
    "priority": 10,
    "enabled": true
  }'
```

### Step 3: Point Your App at the Gateway

Now change your application's API base URL:

```python
from openai import OpenAI

client = OpenAI(
    api_key="tf_sk_your_traceform_key",        # Traceform API key (for auth)
    base_url="http://localhost:8090/v1",         # Gateway URL
    default_headers={
        "X-Traceform-Org-ID": "your-org-id"     # Your org ID
    }
)

# Use normally — all calls are now traced!
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Hello!"}]
)
```

That's it. Every LLM call is now traced, cost-tracked, and protected by guardrails.

## n8n Integration

1. In your n8n workflow, add or edit an **OpenAI** node
2. In **Credentials**, create a new OpenAI credential:
   - **API Key:** Your Traceform API key (`tf_sk_...`)
   - **Base URL:** `http://your-traceform-server:8090/v1`
3. In the node settings, add a header:
   - **X-Traceform-Org-ID:** Your org ID (find it in Dashboard → Settings)
4. All LLM calls from this node are now traced in Traceform

## Flowise / Langflow

1. In your flow, click on the **LLM** component (ChatOpenAI, etc.)
2. Set **Base URL** to `http://your-traceform-server:8090/v1`
3. Set **API Key** to your Traceform API key
4. Add **Custom Headers:** `X-Traceform-Org-ID: your-org-id`

## Dify

1. Go to **Settings → Model Providers**
2. Add a custom OpenAI-compatible provider:
   - **API Base URL:** `http://your-traceform-server:8090/v1`
   - **API Key:** Your Traceform API key
3. Use this provider in your Dify apps

## Any OpenAI-Compatible Client

Any tool or library that supports a custom `base_url` for OpenAI works:

```bash
# curl
curl http://localhost:8090/v1/chat/completions \
  -H "Authorization: Bearer tf_sk_your_key" \
  -H "X-Traceform-Org-ID: your-org-id" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-4o", "messages": [{"role": "user", "content": "Hello"}]}'
```

```typescript
// TypeScript
import OpenAI from 'openai';

const client = new OpenAI({
  apiKey: 'tf_sk_your_key',
  baseURL: 'http://localhost:8090/v1',
  defaultHeaders: { 'X-Traceform-Org-ID': 'your-org-id' }
});
```

```python
# Python with requests
import requests

response = requests.post(
    "http://localhost:8090/v1/chat/completions",
    headers={
        "Authorization": "Bearer tf_sk_your_key",
        "X-Traceform-Org-ID": "your-org-id",
    },
    json={
        "model": "gpt-4o",
        "messages": [{"role": "user", "content": "Hello"}]
    }
)
```

## What Gets Traced

When using the gateway, Traceform automatically captures:

- **Request:** model, messages, parameters (temperature, max_tokens)
- **Response:** completion text, finish reason
- **Usage:** prompt tokens, completion tokens, total tokens
- **Cost:** calculated from model pricing table
- **Latency:** end-to-end request duration
- **Provider:** which provider handled the request
- **Cache:** whether the response came from semantic cache

## Local Models (LMStudio, Ollama)

You can also route through local models:

```bash
# Add LMStudio as a provider
curl -X POST http://localhost:8080/v1/gateway/providers \
  -H "Authorization: Bearer tf_sk_your_key" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "lmstudio",
    "display_name": "LMStudio",
    "api_key": "lm-studio",
    "base_url": "http://localhost:1234/v1",
    "is_enabled": true
  }'
```

Then route specific models to it and all local model calls are traced alongside your cloud calls.
