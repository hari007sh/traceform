# Trace (Observability)

Trace is Traceform's observability module. It captures every session, span, and event from your AI agents, stores them in ClickHouse for fast aggregation, and surfaces failure patterns, error groups, and alert conditions.

## Overview

Trace gives you:

- **Sessions**: Top-level execution units for an agent run, with status, duration, cost, and token counts.
- **Spans**: Individual operations within a session (LLM calls, tool calls, retrievals, chains, agent steps).
- **Events**: Arbitrary timestamped events attached to sessions or spans.
- **Error Groups**: Errors grouped by fingerprint with ClickHouse aggregation, displayed at `/dashboard/errors`.
- **Failure Patterns**: Pre-built and custom patterns that match against session data to detect recurring failures.
- **Alerts**: Rules that trigger notifications when conditions are met (failure rate thresholds, latency spikes, etc.).

## Dashboard Features

### Split-Pane Session Explorer (`/dashboard/sessions`)

The sessions page uses a master-detail split view instead of a traditional table:

- **Left pane**: Session list with infinite scroll and server-side pagination. Supports search by agent name, filtering by status, and date range filtering via the time range picker.
- **Right pane**: Session detail panel showing the D3 Gantt chart timeline, span tree, metadata, and healing intervention markers.
- **Keyboard navigation**: Use arrow keys (up/down) to move between sessions in the list. The detail pane updates immediately.
- **Server-side operations**: All pagination, search, and filtering happens server-side. The client never loads the full dataset.

### Time Range Picker

A global time range picker appears on all data pages. Preset ranges:

| Preset | Range |
|--------|-------|
| 15m | Last 15 minutes |
| 1h | Last 1 hour |
| 4h | Last 4 hours |
| 1d | Last 24 hours |
| 7d | Last 7 days |
| 30d | Last 30 days |

The selected time range is applied to all queries on the page, including analytics charts and session lists.

### Auto-Refresh

The overview page at `/dashboard/overview` supports configurable auto-refresh:

| Interval | Description |
|----------|-------------|
| Off | Manual refresh only |
| 10s | Refresh every 10 seconds |
| 30s | Refresh every 30 seconds |
| 1m | Refresh every 1 minute |

### Session Replay (Gantt Chart)

The session detail panel includes a D3.js Gantt-chart timeline (`SessionReplay` component) that visualizes:

- All spans as horizontal bars on a time axis
- Span nesting (parent-child relationships)
- Span types with color coding
- Duration and overlap between concurrent spans
- Healing intervention markers (cyan pulses) from Shield
- Click any span bar to expand its input/output, model, tokens, and latency

### Virtual Scrolling

For sessions with hundreds or thousands of spans, the span tree uses react-virtuoso for virtual scrolling. Only visible spans are rendered in the DOM, keeping the UI responsive regardless of trace depth.

### LTTB Chart Downsampling

Analytics charts use the Largest-Triangle-Three-Buckets (LTTB) algorithm to downsample time-series data to a maximum of 500 data points. This prevents chart rendering from slowing down on long time ranges while preserving visual fidelity.

## How It Works

### Sessions and Spans Model

A **session** represents a single agent execution from start to finish. Each session contains one or more **spans** that form a tree (spans can have a `parent_id`).

```
Session: "Customer Support Run #1847"
├── Span: agent (root)
│   ├── Span: llm_call (classify intent)
│   ├── Span: tool_call (search_knowledge_base)
│   ├── Span: llm_call (generate response)
│   └── Span: tool_call (send_email)
```

**Session statuses**: `running`, `completed`, `failed`, `timeout`, `healed`

**Span types**: `llm_call`, `tool_call`, `retrieval`, `chain`, `agent`, `custom`

### Data Flow to ClickHouse

1. SDKs send data to ingestion endpoints (`POST /v1/ingest/sessions`, `/spans`, `/events`, `/batch`).
2. The API server publishes each item to a NATS subject (`trace.ingest.session`, `trace.ingest.span`, `trace.ingest.event`).
3. Ingestion uses bounded buffers (50K cap) with dead letter for failed writes.
4. The ingest writer worker subscribes via NATS queue groups and batch-writes to ClickHouse.
5. API responses return `202 Accepted` immediately -- they are never blocked on ClickHouse writes.
6. Query endpoints (`GET /v1/sessions/*`, `GET /v1/analytics/*`) read directly from ClickHouse with Redis query caching (30-60s TTL).

### Error Groups

Errors are grouped by fingerprint, which is computed from:
- Normalized error message (dynamic values like IDs and timestamps stripped)
- Top stack trace frames
- Span type and agent name

Error groups are aggregated in ClickHouse and displayed at `/dashboard/errors` with:
- Error count, first seen, last seen
- Affected agents and span types
- Sample sessions for investigation

### Failure Patterns

Traceform ships with 50+ pre-built failure patterns (seeded from `seed/failure_patterns.json`). The pattern matcher worker periodically scans sessions and flags matches. Examples:

- Infinite loop detected (same tool called 5+ times)
- Token budget exceeded
- Empty response from LLM
- Tool call returned error

### Alerts

Alert rules define conditions that trigger notifications:

- Failure rate exceeds a threshold over a time window
- Average latency exceeds a threshold
- Cost per session exceeds a limit

When conditions are met, the alert evaluator worker triggers the configured action (email via SendGrid, webhook, etc.).

## API Reference

### Ingest Session

```
POST /v1/ingest/sessions
Authorization: Bearer tf_sk_your_key
Content-Type: application/json
```

```json
{
  "id": "sess_abc123",
  "agent_name": "customer-support",
  "status": "completed",
  "input": "How do I reset my password?",
  "output": "Go to Settings > Security > Reset Password.",
  "total_tokens": 1250,
  "total_cost_cents": 3,
  "total_spans": 4,
  "duration_ms": 2340,
  "tags": ["support", "password"],
  "started_at": "2026-03-21T10:30:00Z",
  "ended_at": "2026-03-21T10:30:02.340Z"
}
```

Response (`202 Accepted`):

```json
{
  "status": "accepted",
  "session_id": "sess_abc123"
}
```

### List Sessions

```
GET /v1/sessions?agent_name=customer-support&status=failed&limit=20&offset=0
Authorization: Bearer tf_sk_your_key
```

Query parameters:

| Parameter | Default | Description |
|-----------|---------|-------------|
| `agent_name` | -- | Filter by agent name |
| `status` | -- | Filter by status |
| `limit` | 50 | Number of sessions to return |
| `offset` | 0 | Pagination offset |
| `start_date` | -- | Filter sessions started after this time (RFC3339) |
| `end_date` | -- | Filter sessions started before this time (RFC3339) |
| `search` | -- | Full-text search across agent name, metadata, and tags |

### Error Groups

```
GET /v1/errors?limit=20
Authorization: Bearer tf_sk_your_key
```

```
GET /v1/errors/{fingerprint}
Authorization: Bearer tf_sk_your_key
```

### Analytics Overview

```
GET /v1/analytics/overview?period=24h
Authorization: Bearer tf_sk_your_key
```

Returns aggregate metrics: total sessions, failure rate, average duration, total cost, reliability score. Results are cached in Redis (30s TTL).

### Sessions Over Time

```
GET /v1/analytics/sessions-over-time?start=...&end=...&interval=3600
Authorization: Bearer tf_sk_your_key
```

Returns time-series data downsampled to max 500 points via LTTB.

### Data Export

```
GET /v1/export/sessions?format=csv&start=...&end=...
Authorization: Bearer tf_sk_your_key
```

Export sessions as CSV or JSON. Requires cloud plan or above.
