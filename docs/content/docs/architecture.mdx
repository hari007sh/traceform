# Architecture

Traceform is composed of four application components backed by four infrastructure services, with RBAC enforcement, query caching, circuit breakers, and bounded ingestion buffers throughout. This page describes how they connect, how data flows through the system, and how authentication and authorization work.

## Application Components

### API Server (Go, port 8080)

The unified REST API server handles all module endpoints. Built with Go 1.26+ and the [go-chi/chi](https://github.com/go-chi/chi) router. The server binary is at `cmd/server/main.go`.

On startup, it connects to all four infrastructure services (PostgreSQL, ClickHouse, Redis, NATS), initializes module handlers, and registers routes. Middleware includes:

- **Request logging**: Structured JSON via `log/slog`
- **CORS**: Configurable origins
- **Rate limiting**: Redis sliding window (1000/min query, 10000/min ingest)
- **Body size limits**: 10MB on all endpoints
- **Request ID propagation**: UUID per request
- **Request timeout**: 30 seconds
- **RBAC enforcement**: Owner/admin/viewer roles on all mutation routes
- **Plan gating**: Feature enforcement by plan tier (free/cloud/team/enterprise)

```go
// cmd/server/main.go — initialization sequence
cfg, _ := config.Load()
db, _ := sql.Open("pgx", cfg.DatabaseURL)          // PostgreSQL
chDB, _ := sql.Open("clickhouse", cfg.ClickhouseURL) // ClickHouse
redisClient := redis.NewClient(opt)                   // Redis
natsConn, _ := nats.Connect(cfg.NatsURL)              // NATS

srv := server.New(cfg, db, redisClient, natsConn, server.WithClickHouse(chDB))
srv.Run()
```

The server degrades gracefully: if ClickHouse is unavailable, session/analytics queries return errors but ingestion still works (events queue in NATS). If Redis is unavailable, rate limiting is disabled. If NATS is unavailable, ingestion falls back to synchronous writes.

### Gateway Proxy (Go, port 8090)

A separate Go binary (`cmd/gateway/main.go`) that acts as an OpenAI-compatible proxy. It exposes:

- `POST /v1/chat/completions` -- chat completions with routing, caching, and guard checks
- `POST /v1/embeddings` -- embedding requests with routing

Key features added since initial build:

- **Circuit breakers**: Per-provider circuit breakers that open after consecutive failures and close after a cooldown period. Prevents cascading failures when a provider is down.
- **Singleflight cache**: Deduplicates concurrent identical requests so only one hits the upstream provider.
- **Streaming with context cancellation**: Properly cancels upstream requests when the client disconnects mid-stream.
- **Cost recording fix**: Accurately records token usage and cost for both streaming and non-streaming responses.

The proxy adds less than 5ms overhead. It uses an in-memory route/provider cache that refreshes every 30 seconds. Provider API keys are stored encrypted (AES-256-GCM) in PostgreSQL and decrypted at runtime.

### Worker (Go)

Background worker binary (`cmd/worker/main.go`) that consumes from NATS and handles:

| Worker | NATS Subject | Purpose |
|--------|-------------|---------|
| Ingest Writer | `trace.ingest.session`, `trace.ingest.span`, `trace.ingest.event`, `trace.ingest.healing` | Batch-writes to ClickHouse |
| Pattern Matcher | -- | Matches sessions against failure patterns |
| Alert Evaluator | -- | Checks alert rules and sends notifications |
| Test Executor | `test.run.execute` | Runs test suites asynchronously |
| Budget Checker | -- | Recalculates spend and resets expired periods (every 60s) |
| Cache Cleanup | -- | Expires stale semantic cache entries |
| Audit Logger | -- | Async audit log writes (never blocks mutation requests) |
| Error Fingerprinter | -- | Groups errors by fingerprint for the error groups page |

### Dashboard (Next.js, port 3001)

The unified web UI built with Next.js 14+ (App Router), Tailwind CSS, shadcn/ui, and Framer Motion. All six modules share a single sidebar navigation.

Dashboard features added since initial build:

- **Split-pane session explorer**: Master-detail view replacing the original sessions table. Left pane has infinite scroll with server-side pagination, search, and filtering. Right pane shows session detail with the D3 Gantt chart.
- **Time range picker**: Global picker on all data pages with presets (15m, 1h, 4h, 1d, 7d, 30d).
- **Auto-refresh**: Configurable on the overview page (Off/10s/30s/1m).
- **Virtual scrolling**: react-virtuoso for span trees with thousands of spans.
- **LTTB chart downsampling**: Max 500 data points for charts to keep rendering fast.
- **Keyboard navigation**: Arrow keys to navigate sessions in the split-pane explorer.
- **Error groups page**: `/dashboard/errors` shows errors grouped by fingerprint with ClickHouse aggregation.
- **Data export**: CSV/JSON export for sessions, cost data, and audit logs.
- **Billing page**: Plan comparison, usage meters, upgrade buttons.
- **SSO settings page**: SAML and OIDC configuration.
- **Audit log page**: Searchable audit trail of all mutations.

## Data Flow

### 1. SDK to API Server

SDKs (Python and TypeScript) send data to the API server on port 8080:

- **Trace spans** via `POST /v1/ingest/spans`
- **Sessions** via `POST /v1/ingest/sessions`
- **Healing events** via `POST /v1/ingest/healing`
- **Guard checks** via `POST /v1/guard/check`
- **Cost events** via `POST /v1/cost/events`
- **Batch data** via `POST /v1/ingest/batch`

All ingestion endpoints return `202 Accepted` immediately.

### 2. Bounded Ingestion Pipeline

High-volume ingestion data is published to NATS subjects for async processing. The pipeline uses bounded buffers to prevent memory exhaustion:

- **Buffer capacity**: 50,000 events maximum
- **Dead letter**: Events that fail after max retries are written to the dead letter path on disk
- **Queue groups**: NATS queue groups distribute work across multiple worker instances
- **Batch size**: Configurable (default 10,000 per flush)
- **Flush interval**: Configurable (default 5 seconds)

```
trace.ingest.session  → session data
trace.ingest.span     → span data
trace.ingest.event    → event data
trace.ingest.healing  → healing events
test.run.execute      → test run execution requests
```

### 3. NATS to Workers to ClickHouse

Background workers subscribe to NATS subjects and batch-write to ClickHouse. ClickHouse is append-only -- rows are never updated.

### 4. API Server to PostgreSQL

Configuration and CRUD data goes directly to PostgreSQL:

- Users, organizations, memberships (RBAC roles), API keys
- SSO configurations (SAML/OIDC)
- Audit logs (async writes)
- Test suites, cases, evaluators, runs
- Guard rules and events
- Routes, providers, fallback chains
- Budgets, cost events, model pricing
- Alert rules, failure patterns
- Plan tiers, usage metering

### 5. API Server to Redis

- **Rate limiting**: Sliding window algorithm per API key
- **Query cache**: Cached responses on analytics endpoints (30-60s TTL)
- **JWT blacklist**: Revoked tokens stored until expiry (via `POST /auth/logout`)
- **Session cache**: Temporary session state

### 6. Gateway Proxy Pipeline

When a request hits the gateway proxy:

1. Authenticate via `X-Traceform-Org-ID` header
2. Check circuit breaker state for the target provider
3. Check singleflight cache for concurrent identical requests
4. Check semantic cache (Redis fast path, PostgreSQL slow path)
5. Match routing rules (glob pattern on model name)
6. Select provider via strategy (priority, round_robin, or cost)
7. Forward request to provider (with context cancellation on client disconnect)
8. Record cost event with accurate token counts
9. Store response in cache
10. Log request asynchronously via NATS

### 7. Dashboard to API Server

The Next.js dashboard reads from all API endpoints to display data across all six modules. Analytics endpoints benefit from Redis query caching with 30-60 second TTL.

## Authentication Model

Traceform uses three authentication mechanisms:

### API Keys (SDK Authentication)

SDKs authenticate with API keys prefixed `tf_sk_`. Keys are SHA-256 hashed before storage. On each request, the middleware hashes the provided key and looks it up in the `api_keys` table, resolving the associated `org_id`. The `last_used_at` timestamp is updated asynchronously.

```bash
curl -H "Authorization: Bearer tf_sk_your_key_here" \
  http://localhost:8080/v1/sessions
```

API keys support rotation via `POST /api/api-keys/{id}/rotate`, which issues a new key while keeping the old one valid for a 24-hour grace period.

### JWT (Dashboard Authentication)

The dashboard uses JWT tokens issued after GitHub OAuth or SSO login. Tokens are created by `auth.JWTManager` using the `JWT_SECRET` environment variable and verified on every dashboard API request.

JWT revocation is supported via `POST /auth/logout`, which adds the token to a Redis blacklist until it expires naturally.

### DualAuth (Both)

Some endpoints accept either authentication method. The middleware checks for a `Bearer` token first -- if it starts with `tf_sk_`, it is treated as an API key; otherwise, it is decoded as a JWT.

### SSO (Enterprise)

SSO authentication supports both SAML and OIDC protocols with JIT (Just-In-Time) user provisioning. SSO flows are available at:

- `GET /auth/sso/lookup` -- Domain lookup to determine SSO configuration
- `POST /auth/saml/acs` -- SAML Assertion Consumer Service
- `GET /auth/oidc/{orgID}/login` -- OIDC login initiation
- `GET /auth/oidc/callback` -- OIDC callback

## RBAC Model

All mutation routes enforce role-based access control with three roles:

| Role | Permissions |
|------|------------|
| **owner** | Full access. Manage billing, SSO, delete org, transfer ownership. |
| **admin** | Create/update/delete resources. Manage team members (except owners). Manage API keys. |
| **viewer** | Read-only access to all data. Cannot create, update, or delete resources. |

Roles are stored in the `memberships` table linking users to organizations.

## ClickHouse Optimizations

ClickHouse tables use several optimizations for query performance:

- **Skip indexes**: `minmax` and `set` indexes on `org_id`, `agent_name`, `status`, and timestamp columns for fast filtering.
- **ZSTD compression**: All string and JSON columns use ZSTD codec for storage efficiency.
- **Materialized views**: Pre-aggregated views for common analytics queries (sessions over time, failure rates, cost by model).
- **Partitioning**: Tables partitioned by month (`toYYYYMM(started_at)`) for efficient data lifecycle management.

## Error Fingerprinting

Errors are grouped by fingerprint using a combination of:
- Error message (normalized to remove dynamic values)
- Stack trace (top N frames)
- Span type and agent name

Error groups are aggregated in ClickHouse and exposed at `/v1/errors` and `/v1/errors/{fingerprint}`.

## Audit Logging

All mutations (creates, updates, deletes) generate audit log entries asynchronously. The audit log service never blocks the mutation request -- writes go through a channel to the audit logger worker. Audit logs include:

- Actor (user ID and email)
- Action (create, update, delete)
- Resource type and ID
- Before/after state diff
- IP address and user agent
- Timestamp

Audit logs are queryable at `/api/audit-logs` and exportable as CSV/JSON.
