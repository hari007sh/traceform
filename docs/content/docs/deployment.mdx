# Deployment

Traceform can be deployed locally for development using Docker Compose, to production using Docker images and Kubernetes with Helm, or behind a Caddy reverse proxy for TLS termination. A full GitHub Actions CI/CD pipeline is provided.

## Local Development (Docker Compose)

### Prerequisites

- Docker and Docker Compose
- Go 1.26+
- Node.js 20+

### 1. Start Infrastructure Services

```bash
docker compose up -d
```

This starts PostgreSQL, ClickHouse, Redis, and NATS:

| Service | Container Port | Host Port | Purpose |
|---------|---------------|-----------|---------|
| PostgreSQL | 5432 | 5432 | Config database |
| ClickHouse | 9000, 8123 | 9000, 8123 | Time-series storage |
| Redis | 6379 | 6379 | Cache, rate limiting, JWT blacklist |
| NATS | 4222, 8222 | 4222, 8222 | Event streaming |

### 2. Configure Environment

```bash
cp .env.example .env
# Edit .env with your values
```

### 3. Run Migrations

```bash
make migrate
```

### 4. Seed Data

```bash
make seed
```

This loads failure patterns, evaluators, guardrails, and model pricing from the `seed/` directory.

### 5. Start the API Server

```bash
make dev
```

The API server starts on port 8080.

### 6. Start the Gateway Proxy (optional)

```bash
go run ./cmd/gateway
```

The gateway proxy starts on port 8090.

### 7. Start the Worker (optional)

```bash
go run ./cmd/worker
```

### 8. Start the Dashboard

Port 3000 may be taken by other applications. Use port 3001:

```bash
cd web && npm install && PORT=3001 npm run dev
```

The dashboard starts on port 3001.

### Verify

```bash
# Health check with dependency status
curl http://localhost:8080/health

# Readiness probe
curl http://localhost:8080/ready

# Check infrastructure services
docker compose ps
```

## Docker Images

Traceform provides three Dockerfiles in the `deploy/` directory. All Go images build with Go 1.26.

### API Server + Worker + Migrate (`deploy/Dockerfile`)

Multi-stage build that produces a single image capable of running as the API server, background worker, or migration runner depending on the command:

```dockerfile
FROM golang:1.26-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /server ./cmd/server
RUN CGO_ENABLED=0 go build -o /worker ./cmd/worker
RUN CGO_ENABLED=0 go build -o /migrate ./cmd/migrate

FROM alpine:3.19
RUN apk add --no-cache ca-certificates
COPY --from=builder /server /server
COPY --from=builder /worker /worker
COPY --from=builder /migrate /migrate
COPY migrations/ /migrations/
COPY seed/ /seed/
EXPOSE 8080
CMD ["/server"]
```

### Gateway Proxy (`deploy/Dockerfile.gateway`)

```dockerfile
FROM golang:1.26-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /gateway ./cmd/gateway

FROM alpine:3.19
RUN apk add --no-cache ca-certificates
COPY --from=builder /gateway /gateway
EXPOSE 8090
CMD ["/gateway"]
```

### Dashboard (`deploy/Dockerfile.web`)

```dockerfile
FROM node:20-alpine AS deps
WORKDIR /app
COPY web/package.json web/package-lock.json* ./
RUN npm ci

FROM node:20-alpine AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY web/ .
ENV NEXT_TELEMETRY_DISABLED=1
RUN npm run build

FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static
USER nextjs
EXPOSE 3000
CMD ["node", "server.js"]
```

## Production Docker Compose

The `deploy/docker-compose.prod.yml` defines all services:

| Service | Image Source | Port | Depends On |
|---------|-------------|------|------------|
| `postgres` | `postgres:16` | 5432 | -- |
| `clickhouse` | `clickhouse/clickhouse-server:latest` | 9000, 8123 | -- |
| `redis` | `redis:7-alpine` | 6379 | -- |
| `nats` | `nats:latest` | 4222, 8222 | -- |
| `migrate` | `deploy/Dockerfile` | -- | postgres, clickhouse |
| `server` | `deploy/Dockerfile` | 8080 | migrate, redis, nats |
| `worker` | `deploy/Dockerfile` | -- | migrate, redis, nats |
| `gateway` | `deploy/Dockerfile.gateway` | 8090 | migrate, redis, nats |
| `web` | `deploy/Dockerfile.web` | 3001 | server |

The migrate service runs first (with `condition: service_completed_successfully`), then the application services start.

### Deploy with Production Compose

```bash
cd deploy

# Set required environment variables
export POSTGRES_PASSWORD=your_secure_password
export REDIS_PASSWORD=your_secure_password
export JWT_SECRET=your_jwt_secret_at_least_32_chars
export ENCRYPTION_KEY=your_64_char_hex_string_for_aes256
export GITHUB_CLIENT_ID=your_github_oauth_client_id
export GITHUB_CLIENT_SECRET=your_github_oauth_client_secret
export FRONTEND_URL=https://your-domain.com

# Start everything
docker compose -f docker-compose.prod.yml up -d --build
```

## Kubernetes with Helm

<PlanBadge plan="free" />

A full Helm chart is available at `deploy/helm/traceform/`. It includes Horizontal Pod Autoscaling (HPA), Pod Disruption Budgets (PDB), and ingress configuration.

### Install

```bash
helm install traceform deploy/helm/traceform/ \
  --namespace traceform \
  --create-namespace \
  --set server.image.tag=latest \
  --set gateway.image.tag=latest \
  --set web.image.tag=latest \
  --set config.jwtSecret=your_jwt_secret \
  --set config.encryptionKey=your_encryption_key \
  --set config.githubClientId=your_client_id \
  --set config.githubClientSecret=your_client_secret
```

### Key Helm Values

```yaml
# Server configuration
server:
  replicas: 2
  resources:
    requests:
      cpu: 250m
      memory: 256Mi
    limits:
      cpu: 1000m
      memory: 1Gi
  hpa:
    enabled: true
    minReplicas: 2
    maxReplicas: 10
    targetCPUUtilization: 70

# Gateway configuration
gateway:
  replicas: 2
  resources:
    requests:
      cpu: 250m
      memory: 128Mi

# Worker configuration
worker:
  replicas: 1

# Web dashboard
web:
  replicas: 2

# Ingress
ingress:
  enabled: true
  className: nginx
  hosts:
    - host: traceform.example.com
      paths:
        - path: /
          service: web
        - path: /v1
          service: server
        - path: /api
          service: server
        - path: /auth
          service: server
        - path: /health
          service: server
        - path: /ready
          service: server
        - path: /metrics
          service: server
  tls:
    - secretName: traceform-tls
      hosts:
        - traceform.example.com

# Pod Disruption Budget
pdb:
  enabled: true
  minAvailable: 1
```

### Upgrade

```bash
helm upgrade traceform deploy/helm/traceform/ \
  --namespace traceform \
  --set server.image.tag=v1.2.0
```

## Caddy TLS Reverse Proxy

<PlanBadge plan="free" />

A Caddy configuration is provided at `deploy/caddy/` for TLS termination and reverse proxying.

### Caddyfile

```
traceform.example.com {
    # API server
    handle /v1/* {
        reverse_proxy server:8080
    }
    handle /api/* {
        reverse_proxy server:8080
    }
    handle /auth/* {
        reverse_proxy server:8080
    }
    handle /health {
        reverse_proxy server:8080
    }
    handle /ready {
        reverse_proxy server:8080
    }
    handle /metrics {
        reverse_proxy server:8080
    }

    # Gateway proxy
    handle /gateway/* {
        reverse_proxy gateway:8090
    }

    # Dashboard (default)
    handle {
        reverse_proxy web:3001
    }
}
```

### Deploy with Caddy

```bash
cd deploy/caddy
docker compose -f docker-compose.caddy.yml up -d
```

Caddy automatically provisions and renews TLS certificates via Let's Encrypt.

## GitHub Actions CI/CD

A comprehensive CI/CD pipeline is provided at `.github/workflows/ci.yml`. It includes:

### Pipeline Stages

1. **Go tests**: Runs `go test ./...` with race detection
2. **Python SDK tests**: Runs `pytest` in the SDK directory
3. **Frontend checks**: Runs `npm run lint` and `npm run build` in the web directory
4. **E2E tests**: Starts full Docker Compose stack, runs integration tests
5. **Docker builds**: Builds all three Docker images (server, gateway, web)
6. **Helm lint**: Validates the Helm chart
7. **Security scanning**: Runs `govulncheck` for Go dependencies, `npm audit` for Node.js

### Triggering

The pipeline runs on:
- Push to `main` branch
- Pull requests targeting `main`
- Manual dispatch

## Monitoring with Prometheus and Grafana

<PlanBadge plan="free" />

### Prometheus Scrape Configuration

Add Traceform to your Prometheus targets:

```yaml
scrape_configs:
  - job_name: 'traceform-server'
    static_configs:
      - targets: ['server:8080']
    metrics_path: /metrics
    scrape_interval: 15s
```

### Grafana Dashboards

Pre-built Grafana dashboards are available in `deploy/grafana/`. Import them into your Grafana instance for:

- **API Server**: Request rates, latencies, error rates, active connections
- **Gateway**: Provider latencies, circuit breaker states, cache hit rates
- **Ingestion**: NATS queue depth, ClickHouse write latency, dead letter counts
- **Business Metrics**: Sessions per minute, healing events, guard checks, cost tracking

## Backup and Restore

### PostgreSQL

```bash
# Backup
pg_dump -h localhost -U agentstack agentstack > backup.sql

# Restore
psql -h localhost -U agentstack agentstack < backup.sql
```

### ClickHouse

```bash
# Backup a table
clickhouse-client --query "SELECT * FROM sessions FORMAT Native" > sessions.native

# Restore a table
clickhouse-client --query "INSERT INTO sessions FORMAT Native" < sessions.native
```

## Production Checklist

Before going to production, ensure:

- [ ] `JWT_SECRET` is set to a strong random value (not the default)
- [ ] `ENCRYPTION_KEY` is set to a cryptographically random 64-character hex string
- [ ] `POSTGRES_PASSWORD` and `REDIS_PASSWORD` are strong and unique
- [ ] `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` are configured
- [ ] `FRONTEND_URL` points to your actual dashboard domain
- [ ] PostgreSQL has `sslmode=require` in production
- [ ] Redis has `requirepass` set
- [ ] NATS has authentication configured
- [ ] TLS is configured via Caddy, nginx, or cloud load balancer
- [ ] Prometheus is scraping the `/metrics` endpoint
- [ ] Backup strategy is in place for PostgreSQL and ClickHouse
- [ ] `INGEST_MAX_BUFFER_SIZE` is tuned for your throughput
- [ ] `DEAD_LETTER_PATH` is on persistent storage
- [ ] Resource limits are set in Kubernetes (or Docker `--memory` / `--cpus`)
